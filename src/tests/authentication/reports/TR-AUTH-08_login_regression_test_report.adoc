== Defects Found & Resolved

Every regression below was introduced by code merged onto the branch since
the original TC-AUTH-04 was authored. All four were resolved during this
execution; the fixes are in `src/tests/authentication/scripts/login.test.tsx`.

=== DEF-AUTH-08-01 — `getSession` mock missing

*Found in:* `src/tests/authentication/scripts/login.test.tsx` (Supabase mock)

*Root cause:* PR #694 added a mount-effect call to
`supabase.auth.getSession()` (`src/app/login/index.tsx:149`). The legacy
TC-AUTH-04 mock did not stub it, so every `render(<LoginScreen />)` threw
`TypeError: _supabase.supabase.auth.getSession is not a function`.

*Evidence (excerpt — captured during the baseline run):*

[source]
----
TypeError: _supabase.supabase.auth.getSession is not a function

   128 |   useEffect(() => {
   129 |     const checkExistingSession = async () => {
 > 130 |       const { data: { session } } = await supabase.auth.getSession();
       |                                                         ^
   131 |       console.log('[Login Screen] Existing session check:', {
   132 |         hasSession: !!session,
   133 |         user: session?.user?.email,

   at getSession (src/app/login/index.tsx:130:57)
----

*Resolution:* Added `mockGetSession` to the `jest.mock("../../../lib/supabase", ...)`
factory, resolving with `{ data: { session: null } }`.

=== DEF-AUTH-08-02 — `onAuthStateChange` subscription mock missing

*Found in:* `src/tests/authentication/scripts/login.test.tsx` (Supabase mock)

*Root cause:* A second mount-effect was added that subscribes to
`supabase.auth.onAuthStateChange` and destructures
`data.subscription.unsubscribe` for cleanup
(`src/app/login/index.tsx:160–176`). Without a stub returning that shape,
render or unmount throws.

*Resolution:* Added `mockOnAuthStateChange` returning
`{ data: { subscription: { unsubscribe: jest.fn() } } }`.

=== DEF-AUTH-08-03 — Stale Google OAuth assertion

*Found in:* `src/tests/authentication/scripts/login.test.tsx`
(STEP 5 assertion, pre-patch)

*Root cause:* PR #745 replaced the
"Google sign-in is not enabled yet. Please sign in with email and password."
placeholder with a real OAuth flow. The legacy TC-AUTH-04 assertion still
expected that placeholder text and would have failed on a real run.

*Resolution:* Rewrote STEP 5 to exercise the real Google OAuth call path —
asserting that `signInWithOAuth` is invoked with `provider: 'google'`,
`WebBrowser.openAuthSessionAsync` is opened with the returned URL, and the
cancel branch surfaces `"Google sign in was cancelled."`. The user-cancel
path was chosen because it is deterministic in a Jest environment (no real
network or browser).

=== DEF-AUTH-08-04 — `expo-web-browser` crashes at import in Jest

*Found in:* Jest module loader for any test that imports `LoginScreen`

*Root cause:* PR #745 added `import * as WebBrowser from 'expo-web-browser'`
and called `WebBrowser.maybeCompleteAuthSession()` at module load
(`src/app/login/index.tsx:3, 24`). In a non-Expo runtime that call hits
`AppState.currentState` which is undefined, crashing the whole test module
before any test runs.

*Evidence (excerpt — captured during the baseline run):*

[source]
----
Test suite failed to run

TypeError: Cannot read properties of undefined (reading 'currentState')

    at Object.currentState (node_modules/expo-web-browser/src/WebBrowser.ts:342:46)
    at Object.require (src/app/login/index.tsx:3:1)
    at Object.require (src/tests/authentication/scripts/login.test.tsx:50:1)
----

*Resolution:* Added a Jest module mock for `expo-web-browser` that stubs
`maybeCompleteAuthSession` and `openAuthSessionAsync`. This unblocks the
suite and lets the Google OAuth cancel path be asserted deterministically.

== Notes

* The PASS verdict reflects the state **after** the four defect resolutions
  above. The pre-patch baseline failed catastrophically (suite did not load),
  which is the strongest possible regression signal — the changes that
  landed since TC-AUTH-04 was authored were never re-validated against the
  jest suite.
* The Playwright UI suite (`login.spec.ts`) ran cleanly on Chromium even
  before the jest fixes, because Playwright drives the real Expo web server
  rather than the Jest module loader — so the regression was hidden in the
  unit/integration layer specifically. This confirms the value of running
  both layers as part of login regression going forward.
* No console errors observed during the post-patch passing runs (only the
  benign `[Login Screen] Existing session check` and `Auth state changed`
  diagnostic logs from the production code).
* Apple sign-in remains intentionally a placeholder. STEP 12's assertion
  now guards that contract; a future Apple OAuth wire-up will deliberately
  fail this step and force a regression review at the right moment.
