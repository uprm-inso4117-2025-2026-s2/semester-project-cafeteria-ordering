== Overview

This document defines the usability testing plan for the cafeteria ordering system with emphasis on authentication and security-related workflows. The goal is to evaluate how real users interact with the system while ensuring the platform remains secure, efficient, accessible, and easy to use.

The testing plan follows user-centered design principles and industry-standard usability evaluation methodologies.

== Purpose

The purpose of this usability testing plan is to:

* Evaluate how users interact with authentication and security features
* Identify usability problems that affect authentication and security-related workflows
* Improve overall user satisfaction and efficiency
* Reduce user errors during login and first time registration
* Ensure accessibility for all users
* Validate whether the system supports real cafeteria usage scenarios

== Definitions

=== Usability

Usability refers to how effectively, efficiently, and satisfactorily users can interact with a system to achieve their goals.

A usable system allows users to:

* Learn quickly
* Complete tasks efficiently
* Avoid errors
* Recover from mistakes easily
* Feel satisfied while using the platform

== Nielsen’s Usability Quality Components

The testing plan incorporates Nielsen’s five usability quality components.

=== Learnability

New users should understand how to:

* Create an account
* Log in securely
* Recover passwords

=== Efficiency

Frequent users should complete actions quickly with minimal effort.

Examples:

* Fast login process
* Intuitive creation of account process

=== Memorability

Users returning after a period of inactivity should still remember how to use the platform without relearning the interface.

=== Errors

The system should:

* Prevent common mistakes
* Clearly explain errors
* Help users recover easily

Examples include:

* Incorrect password handling
* Password specifications not satisfied

=== Satisfaction

Users should feel comfortable and confident while using the cafeteria ordering system.

Important factors include:

* Clean interface
* Responsive design
* Clear feedback messages
* Trust in authentication and account security

== Common Cafeteria Ordering Workflows

=== Workflow 1: User Registration

Steps:

. Open app to registration page
. Enter personal information
. Create secure password
. Submit registration form
. Verify account confirmation

=== Workflow 2: User Login

Steps:

. Open login page
. Enter username/email
. Enter password
. Authenticate successfully
. Access home page

=== Workflow 3: Password Recovery

Steps:

. Select "Forgot Password"
. Enter email address
. Receive reset link
. Create new password
. Log in again

=== Workflow 4: Staff Login 

Steps:

. Open login page
. Enter username/email
. Enter password
. Authenticate successfully
. Access staff dashboard

=== Accessibility Testing

Accessibility testing evaluates support for:

* Navigation
* Screen readers
* Color contrast
* Responsive layouts

== Testing Environment

Testing should be performed on:

* Tablets
* Mobile devices

== Test Scenarios

=== Scenario 1: New User Registration

Objective:

Evaluate whether new users can successfully create an account without assistance.

Expected Result:

User completes registration in less than 3 minutes with minimal errors.

=== Scenario 2: Secure Login

Objective:

Measure how efficiently users authenticate into the system.

Expected Result:

User logs in successfully without confusion regarding credentials.

=== Scenario 3: Incorrect Password Recovery

Objective:

Evaluate recovery workflow usability.

Expected Result:

Users understand error messages and recover accounts successfully.

=== Scenario 4: Accessibility Navigation

Objective:

Verify accessibility compliance for assistive technology users.

Expected Result:

All major workflows remain accessible.

== Methods for Collecting Feedback

=== Observation

Researchers observe:

* Navigation patterns
* User hesitation
* Repeated errors
* Confusing interactions

=== Surveys

Post-test surveys measure:

* Ease of use
* Satisfaction
* Confidence in system security

=== Interviews

Short interviews help gather:

* User opinions
* Suggestions for improvement
* Pain points

=== System Analytics

Analytics can collect:

* Task completion times
* Click frequency
* Error occurrence rates
* Session duration
